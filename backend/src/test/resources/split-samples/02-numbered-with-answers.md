# MySQL 高频面试题（附答案）

## 1. 什么是 MySQL 的 MVCC？

MVCC 是多版本并发控制。每行记录有隐藏的事务 id 和回滚指针，旧版本串成版本链，读操作通过 ReadView 判断该看哪个版本。

那为什么读已提交和可重复读的表现不一样呢？区别在于 ReadView 生成的时机：前者每次查询都生成，后者只在第一次查询时生成。

## 2. InnoDB 为什么用 B+ 树做索引？

- 非叶子节点只存键，一页能放更多键，树更矮，磁盘 IO 少
- 叶子节点用链表相连，范围查询方便

为什么不用红黑树？红黑树是二叉的，数据量大时树太高。

Q3: 一条 SQL 很慢，你会怎么分析？

答：先看慢查询日志定位语句，再用 explain 看执行计划：

```sql
EXPLAIN SELECT * FROM orders WHERE user_id = 42 ORDER BY created_at DESC;
```

重点看 type、key、rows 和 Extra 中有没有 Using filesort。

**4. 什么情况下索引会失效？**

答：对索引列做函数运算、隐式类型转换、联合索引不满足最左前缀、like 以 % 开头等。

5、redo log 和 binlog 有什么区别？

参考答案：redo log 是 InnoDB 的物理日志，循环写，用于崩溃恢复；binlog 是 Server 层的逻辑日志，追加写，用于主从复制和数据恢复。

6. 为什么需要两阶段提交？
答：保证 redo log 和 binlog 的一致性。如果先写完一个再写另一个，中间崩溃会怎样？主从数据就会不一致。

7. MySQL 的隔离级别有哪些？默认是哪个？
答：读未提交、读已提交、可重复读、串行化，InnoDB 默认可重复读。

8. 说说间隙锁的作用
答：锁住索引记录之间的间隙，防止其他事务插入，在可重复读级别下用来解决幻读。
