# 023 前端骨架

## 背景

#47 搭前端的骨架：项目配置、设计变量、请求封装、登录状态、路由、布局、快捷键、注册与登录页。后面的页面（今天、导入、知识库、设置、学习）都建在它上面，所以这里定下的写法会被反复使用。作者从零学前端（决策 007），每个文件都要读得懂，依赖越少越好。

设计方向见决策 021，具体数值以 `docs/design/ui.md` 为准。

## 决策

### 1. 手写最小配置，不用脚手架

`frontend/` 下的 package.json、vite.config.ts、tsconfig 都是手写的，tsconfig 参照 create-vue 3.24.0。依赖：

| 运行时 | 开发时 |
| --- | --- |
| vue 3.5.44、vue-router 5.4.0、element-plus 2.14.7、@fontsource/noto-serif-sc 5.3.1 | vite 8.3.4、@vitejs/plugin-vue 6.0.10、typescript 6.0.3、vue-tsc 3.3.13、@vue/tsconfig 0.9.1、@types/node 24.19.2 |

- 版本写死（不带 `^`），都选发布满两周的最新版
- typescript 用 6.0，不用 7.0：vue-tsc 依赖 TS 5、6 的 JS 接口
- 不用 axios、Pinia、unplugin 自动导入，暂不加 Vitest

### 2. 宋体随前端打包

标题用的 Noto Serif SC 由 `@fontsource/noto-serif-sc` 提供，只引入 700 一个字重。字体按字符范围切成约 100 个小文件，浏览器只下载页面上用到的那几个。正文的黑体不打包，用系统字体（PingFang、微软雅黑）。

### 3. 主题用 CSS 变量

- `styles/tokens.css`：ui.md 第 2 节的全部变量，定义在 `:root` 上，组件中不写死色值
- `styles/element.css`：把 Element Plus 的变量（`--el-color-primary` 等）映射到设计变量。Element Plus 用 SCSS 在构建时算出主色的深浅变体，这里改用 `color-mix()` 在浏览器中计算
- 主按钮全局改成浅底、主色文字（决策 021）；输入框、按钮高 44
- 菜单中的危险操作用全局类 `wg-danger`：下拉菜单项由 Element Plus 的内部组件渲染，组件中的 scoped 样式作用不到

### 4. 请求封装 `api/http.ts`

- 用 fetch 解析统一返回格式 `{code, message, data}`，失败时抛出 `ApiError(status, code, message)`，`message` 可以直接显示给用户
- 非 GET 请求每次从 Cookie 现读 `XSRF-TOKEN`，放进请求头 `X-XSRF-TOKEN`（决策 022）
- 收到 401 时调用路由注册进来的处理函数：清掉当前用户，跳到登录页并记下原路径。http 不直接引用路由，免得路由、页面、接口之间循环引用。登录接口和查询当前用户的接口不跳转，由调用方处理
- 连不上服务器、后端没启动（开发代理返回的不是统一格式）时，给出可以理解的提示

### 5. 当前用户与路由守卫

- `auth/session.ts` 用一个模块级的 `ref` 保存当前用户，对外只暴露只读版本和三个修改函数。全应用只有这一个共享状态，不需要 Pinia
- 路由守卫在第一次导航时调用 `GET /api/auth/me`，之后用缓存，刷新页面后重新查询。并发的查询共用同一个 Promise
- 路由的 `meta`：`guest` 只给没登录的人看（注册、登录），已登录时直接进入应用；`public` 谁都能看（协议页）；其他都要求登录
- 登录后跳回的 `redirect` 只接受以 `/` 开头、且不以 `//` 或 `/\` 开头的站内路径，防止链接被构造成登录后跳到别的网站
- 连不上后端时当作没登录，停在登录页，提交时显示原因

### 6. 两种布局用嵌套路由区分

- 应用框架 `AppLayout`：左侧导航（图标路径直接取自设计稿，不引入图标库）+ 账户区菜单 + 内容区。各页面的顶栏用 `PageHeader` 组件
- 学习模式 `StudyLayout`：没有侧栏，内容居中，最宽 760。顶栏中间的进度和右边的时长由 #23 加上
- 注册、登录、协议页不套这两种布局。注册页和登录页共用 `AuthPage`，左栏是独立组件 `AuthShowcase`（ui.md 5.1）
- 窄屏时侧栏、左栏换到主内容下方（ui.md 4.3），表单和内容在前

### 7. 快捷键 `useShortcut`

- 组件中调用 `useShortcut('Enter', handler)`，挂载时生效，卸载时移除；`Mod+Enter` 中的 Mod 在 Windows 上是 Ctrl，在 Mac 上是 Cmd
- 单键快捷键在这些情况下不生效：焦点在输入框、文本框、下拉框、可编辑区域中；焦点在弹窗中；按 Enter 时焦点在按钮或链接上（这时 Enter 本来就会点击它）。输入法组字时的 Enter 也不算
- 需要在输入框中生效的单键（如接着问页面的 Esc）显式传 `allowInInput`
- 快捷键列表集中在 `shortcuts/list.ts`，按 `?` 弹出的列表和以后设置页的列表都从这里读

### 8. 注册与登录页

- 注册时在前端提前检查，规则和后端 `UserService` 一致（用户名正则、密码字符数和 UTF-8 字节数）；最终以后端为准，后端的错误显示在对应的字段或表单上
- 登录只检查有没有填，不重复注册的规则
- 先查注册是否开放，查询完成前不显示表单，免得注册关闭时表单闪一下；关闭时只显示“暂未开放注册”
- 表单标题用黑体，和截图 `01-register.png`、`02-login.png` 一致；ui.md 中“页面主标题用宋体”指应用内的页面

### 9. 暂不写前端自动化测试

用 `vue-tsc` 类型检查、`vite build`，加上在浏览器中走一遍完成标准来验证。

## 验证

- `npm run build`（类型检查 + 打包）通过
- 用无头 Chrome 通过 DevTools 协议走了一遍，连接本地后端：未登录跳转登录页并带上原路径；用户名输入框自动聚焦；空表单、用户名不合规、两次密码不一致的提示；在“确认密码”中按 Enter 注册，进入今天页，账户区显示用户名和首字；刷新后仍登录；已登录打开登录页回到今天页；按 `?` 打开快捷键列表，Esc 关闭；账户菜单退出登录，之后 `/api/auth/me` 为 401；密码错误显示“用户名或密码错误”；登录后回到原来的页面（用户名大小写不敏感）；站外的 `redirect` 被忽略；用户名已被使用；375px 宽度下各页面不横向滚动；没有控制台错误
- 另起一个关闭注册的后端，注册页只显示“暂未开放注册”
- 截图与 `01-register.png`、`02-login.png` 对照一致

## 理由

- **手写配置**：脚手架会带上示例页和 Pinia、ESLint 等用不上的东西；手写的配置每一行都知道为什么在那里
- **字体打包**：Windows 默认没有 Noto Serif SC，退回的 SimSun 没有粗体，浏览器硬描粗后很难看；Google Fonts 在国内经常连不上，而且自部署的应用每次打开都去请求外部网站，有隐私问题
- **CSS 变量**：不需要 sass；以后加暗色模式只需再定义一套变量；`color-mix()` 在 2023 年后的主流浏览器中都能用
- **fetch 封装**：要做的只有解析统一格式、带令牌、处理 401，几十行就够，axios 的拦截器、取消、进度用不上
- **模块级 ref**：只有一个共享状态，Pinia 的 store、devtools 集成用不上
- **路由守卫集中检查登录**：每个页面自己检查容易漏

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| create-vue 生成项目 | 带上很多用不上的文件和依赖，读起来分不清哪些是必要的 |
| axios | 功能用不上，多一个依赖 |
| Pinia | 只有一个共享状态 |
| Element Plus 的 SCSS 变量定制主题 | 多一个 sass 依赖，主题在构建时就定死了 |
| Element Plus 按需引入（unplugin） | 多两个插件，自动导入让代码中看不出组件从哪来（#22 时已确认全量引入） |
| Element Plus 官方图标库 | 只要几个图标，设计稿里有现成的路径 |
| Google Fonts 链接 | 国内经常连不上；隐私 |
| 只用系统字体 | Windows 上标题的宋体粗体很难看 |
| 每个页面自己检查登录 | 容易漏 |
| http 直接引用路由处理 401 | 路由 → 页面 → 接口 → http → 路由，循环引用 |

## 遗留问题

- 全量引入 Element Plus，JS 打包后约 985 KB（gzip 后约 317 KB），构建时有“chunk 超过 500 KB”的提示。M1 自用可以接受；需要时改为按需引入，或把 Element Plus 拆成单独的 chunk
- 字体包同时带了 woff2 和 woff 两种格式，打包产物约 9 MB，其中绝大部分是字体文件。现代浏览器只下载 woff2 中用到的几个，不影响加载速度，只占磁盘
- 浏览器验证脚本没有放进仓库（不引入测试依赖时，它依赖本机安装的 Chrome）；页面多起来后再决定是否引入 Playwright 或 Vitest
