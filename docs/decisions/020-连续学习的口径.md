# 020 连续学习的口径

## 背景

M2 的统计要显示连续学习天数，以后的组队打卡（PRD 想法池）也要用到。要先定下“学了一天”指什么、没有任务的日子怎么算。

统计在 M2 才做，但数据要从 M1 开始记：每日计划不建表、实时计算（技术方案“每日计划的计算逻辑”），card_state 只存现在的状态，review_log 不记评分后的下次到期日。过去某一天有哪些任务、有没有做完，事后算不回来；到 M2 再记，M1 自用期间的数据就补不上了。

## 决策

1. **完成当天全部任务才算一天**。当天没有任何任务时，不计入，也不打断连续
2. **“当天”按用户的时区和 day_start_hour 计算**，与每日计划用同一个学习日（决策 016）
3. **以后的组队打卡使用同一个口径**
4. **M1 起记录两样数据**：
   - review_log 增加**评分后的下次到期日**。知识库的学习记录、以后的 FSRS 参数优化也要用
   - 某个学习日的计划变空时，写一条**“当天完成”的记录**。这是已经发生的事实，不是计划的快照，不违反“每日计划不建表”。在哪一步写入（评分之后检查、打开计划时检查），由相关 issue 的方案定
5. **当天有没有任务的判断**：有完成记录的日子算一天；没有完成记录的日子，用到期日推算当天有没有到期的复习，以及新知识池是否为空，两者都没有就跳过（不计入，也不打断）；有任务却没有完成记录的，打断连续

## 理由

- **以完成为准**：PRD 的成功指标是“每天都能完成当天任务”，连续天数应当和它一致。只要学一个就算一天，口径太松，连续天数就不说明问题
- **没任务不打断**：只复习不学新的阶段，可能恰好某天没有到期的复习。用户什么都没做错，不应当断掉
- **和每日计划用同一个学习日**：凌晨学习算前一天（决策 016），连续天数也要这样算，否则熬夜学习的人会在零点被算成新的一天
- **记事实，不记快照**：“当天完成”只在发生时写一条，内容是“哪个用户、哪个学习日”，不保存当天的计划。计划仍然实时计算，两份数据不会不同步
- **到期日写进流水**：有了每次评分后的到期日，就能推算出过去任意一天有哪些知识点到期，不用保存计划

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 当天学了任意一个就算一天 | 和“完成当天任务”的成功指标不一致 |
| 没有任务的日子打断连续 | 用户没有做错什么 |
| 按日历日（零点）划分 | 熬夜学习的人会被算到第二天，和每日计划不一致 |
| 建表保存每天的计划快照 | 违反“存事实，算派生”，计划和快照要保持一致 |
| 到 M2 做统计时再开始记录 | M1 自用期间的数据补不回来 |

## 遗留问题

- 推算“新知识池是否为空”时，不知道当天的每天新学数。用户把每天新学数设为 0、当天又没有到期复习时，计划一整天都是空的，不会发生“变空”这件事，可能被误判为“有任务没完成”。在写入完成记录的 issue 方案中处理
