# 044 截图导入

## 背景

导入页要能上传题目截图，用多模态模型识别图中的文字，走现有的题目确认和抽取流程（#88）。要定的是：识别结果能不能先改、图片存不存、张数和大小、同步还是异步、模型不支持图片时怎么办。

明确不做：扫描件 PDF 的 OCR（决策 037）、手写内容的识别、为截图单独配置模型。

## 实验

用自己生成的题目图片试了两个模型：

| 模型 | 结果 |
| --- | --- |
| `deepseek-flash` | 能读图，文字完全正确 |
| 本地 `qwen2.5:7b`（只支持文字） | 返回 400：`Multimodal data provided, but model does not support multimodal requests.` |

所以调用后就能判断，不用提前检测，也不用为截图单独配置模型。

实现后用作者的 3 张真实题库截图走完整流程：`deepseek-flash` 用 35 秒识别出 56 行，抽查一张的 16 行题目，和原图逐字一致；之后切题、抽取、确认都正常。识别结果里带着表格的难度和标签，不影响切题。JPG、WebP 用自己生成的测试图验证过。

## 决策

### 1. 识别结果填进内容框，用户可以先改

识别完切回“粘贴文本”，文字填进内容框，已有内容时追加在后面，之后走现有的“识别题目 → 确认 → 抽取”。这一步只产出文字，不写 `source` 表，不新增资料类型，题目清单和讲解资料都能用。

### 2. 只留文字，图片用完即弃

和上传文件一致（决策 037）。图片只在处理期间留在内存中，不落库，也不写进 Redis。

### 3. 最多 5 张，每张 5 MB，合计 10 MB，支持 PNG、JPG、WebP

合计 10 MB 正好在现有的上传限制内（`spring.servlet.multipart`、Nginx），配置不用改。格式按文件开头的字节判断，不看扩展名和客户端声明的类型。

### 4. 所有图片按顺序一次发给模型

一道题跨两张图也能接上。代价是一次失败要整批重试。

### 5. 异步：提交后拿任务 id，前端轮询

按决策 034，新的耗时 AI 接口优先异步。

- 任务状态放 Redis，键里带 user_id，30 分钟后自动过期，不用写清理代码
- 用专用的小线程池（2 个线程，最多排队 4 个）：每个任务在内存中带着最多 10 MB 的图片，不能无限排队
- 线程池和 Redis 中的任务重启后不恢复：前端轮询超过 5 分钟就提示重试

### 6. 模型不支持图片时给出明确提示

新增返回码 `LLM_IMAGE_UNSUPPORTED`，提示“当前 AI 模型可能不支持图片，可以把题目粘贴成文字”。有两种情况都用它：

- 服务商拒绝带图片的请求（400、422）。这个判断只用于带图片的调用，普通调用的 400 仍然是 `LLM_FAILED`
- 服务商忽略图片、照样回答：提示词要求“没有收到图片时只回答 `NO_IMAGE`”，收到这个标记就当作不支持

这种情况不计入模型状态的失败：模型本身没有坏，不该让头像上出现红点。

## 理由

- **填进内容框**：多点一下，但能改错字，后面的流程一行不用改
- **不用新依赖**：Spring AI 的 `Media` 已经支持图片
- **一次发送**：比逐张调用简单，顺序由模型一起处理

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 识别后直接进题目确认 | 识别错的字没有地方改 |
| 保存图片 | 要加存储，用不上 |
| 每张图单独调用 | 一道题跨两张图时接不上 |
| 同步接口 | 代码少一些，但违反决策 034，多张图可能要几十秒 |
| 调用前检测模型是否支持图片 | 多一次请求，服务商也没有统一的查询方式 |
| 任务状态放内存 | Redis 自带过期，代码更少，以后多实例也不用改 |

## 遗留问题

- 只用两个模型验证过拒绝图片时的表现，别的服务商可能返回别的错误，届时显示通用的“调用失败”
- 一张图里没有文字时提示“图片里没有识别出文字”，靠模型回答 `NO_TEXT` 判断
