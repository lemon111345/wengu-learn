# 047 参考答法读取时切分，不单独存储

## 背景

学习对话的提示词要求收尾时“用三到五句话给出这道题在面试中的参考答法”。这段话只是收尾消息的一部分，没有单独的字段。学完之后想再看它很麻烦：评分页按“下一个”之后回不去；之后要走 知识库 → 详情 → 学习记录 → 回顾页 → 翻到最底下（#111）。之后还要做一个集中查看所有答法的速查页（#112）。

2026-11-13 查开发库：22 条收尾消息全部写了“参考答法”，但写法不统一：`**参考答法**：`、`**面试参考答法**：`、`参考答法：`、`面试参考答法：`、`这道题的参考答法：`、`【参考答法】` 都有，参考答法都在收尾的最后。

## 决策

1. **读取时从收尾消息中切出参考答法，不改提示词，不加列，不做迁移。** 规则：取最后一次出现“参考答法”之后的文字；如果紧跟着 `**`、“如下”“是”和冒号或右方括号，一起去掉；到消息结尾为止。找不到或切出来是空的为 null。开发库的 22 条全部切对。
2. **收尾 = 已结束的学习会话的最后一条老师回复**，不按【学习结束】标记找：回答达到上限时，收尾里可能没有这个标记。接着问、问答会话没有收尾，为 null。
3. 会话接口（`SessionView`）新增 `referenceAnswer` 字段，向后兼容。切分规则放在后端（`ReferenceAnswers`），速查页和以后的小程序共用。
4. 前端只在展开时才取，取过的在页面内缓存；知识库详情里默认折叠，今天页只给已完成的行，避免复习前先看到答案。

## 理由

- 读时切分对旧的学习记录同样有效，不用补数据
- 收尾消息不会再变，没有“存的和显示的不一致”的问题
- 切一次是一次字符串查找，开销可以忽略；速查页一次要切全部学过的知识点，几百条也不是问题

## 放弃的方案

- **改提示词，规定固定格式或加一个新标记，再存成单独的列**：需要迁移，旧记录要另外补；流式输出时新标记还要从内容里去掉。现在的写法虽然不统一，但关键词稳定，按关键词切已经够用
- **前端切分**：切分是业务规则，按决策 034 放在后端，小程序不用再实现一遍
- **给每个知识点单独生成一份固定的参考答法**：多一次模型调用，和“要点”作用重叠，要先讨论清楚，暂不做

## 遗留问题

- 模型哪天不写“参考答法”这几个字，就切不出来，页面退回“看完整对话”。如果自用中经常出现，再改提示词固定写法
- 速查页一次切全部会话，题量上千时再考虑存储或分页
