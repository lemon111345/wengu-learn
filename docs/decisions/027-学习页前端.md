# 027 学习页前端

## 背景

#23 做学习、收尾与评分、接着问三个页面（ui.md 5.3～5.5），把“今天 → 学习 → 评分 → 接着问 → 下一个”这条主线在浏览器里走通。后端的会话、流式对话、评分接口已经在 #19、#20 完成（决策 025、026）。要定的是：

- 页面的地址怎么设计，刷新后怎么恢复
- 流式回复的客户端怎么写（EventSource 只能发 GET）
- 老师回复中的 Markdown（代码块、列表等）怎么显示
- 评分的乐观更新、“下一个”什么时候能点
- 学习模式的顶栏（当天进度、本次分钟数）从哪里取数据

## 决策

### 1. 地址按会话 id，入口按知识点

| 路由 | 作用 |
| --- | --- |
| `/study/:kpId` | 入口：调用 `POST /api/sessions`，拿到会话后换成 `/session/:id` |
| `/session/:id` | 学习；学完后同一页切换成收尾与评分 |
| `/session/:id/follow-up` | 接着问，id 是原来的学习会话 |

按会话 id，刷新评分页不会因为“按知识点重新开始”而新建会话。为此后端补了两处：`GET /api/sessions/{id}` 返回 `activeSeconds` 和已评的分 `rating`；开始学习时，学完了但还没评分的会话也接着用，用户学完没评分就离开，再从今天页进来会回到评分。

### 2. 流式回复用 fetch 自己读流

`api/sse.ts` 用 fetch 发 POST，带上 CSRF 令牌，读响应流，按 SSE 的格式拆出 `delta`、`done`、`error`。推送之前的校验错误（如 409）和普通接口一样抛出 `ApiError`；推送到一半连接断了抛出 `StreamInterrupted`。`http.ts` 抽出 `csrfHeaders`、`errorOf` 两边共用。

### 3. 对话逻辑集中在 `useChat`，以后端的会话为准

学习页和接着问共用一个组合函数：

- 每次流式回复结束（完成、出错、中断）都重新取一次会话，拿到存库的消息、标记、会话是否结束、有效时长；流式进行中只在界面上临时显示学生刚发的话和老师正在说的话
- 刷新时老师还在后台生成（`generating`），每 2 秒取一次会话，直到生成完
- 模型出错：显示提示和“重试”（重新生成这条回复）
- 连接中断：重新取会话，回复已经存下或还在生成时不再提示；否则显示“连接中断”和“重试”
- 离开页面只断开连接，后端照样生成完、存进库（决策 025）

### 4. 老师回复的格式：自己写一个只认几种写法的渲染器

`utils/markdown.ts` 只认代码块（流式中还没闭合的也按代码块显示）、行内代码、加粗、段落、有序和无序列表、标题、表格。**先把全部内容按 HTML 转义，再识别格式**，模型输出的任何标签都只会显示成文字，`v-html` 是安全的。引用、链接、图片等原样显示。学生的回答原样显示、保留换行。

表格起初不在范围内，真实对话中模型用表格画了线程交错的时间线，就补上了。

### 5. 收尾与评分

- 对话区只显示最后三条（要求完整作答的那句、“你的完整作答”、收尾点评），前面的可以展开
- AI 建议在页面打开时请求，生成中显示“AI 正在看你的回答”，失败时显示原因和“重试”；**评分按钮不等它**
- 四个评分按钮不预先选中；按 1～4 选择。选中后立刻按预览的日期显示“X月X日再见”（乐观更新），后台保存；失败撤回，提示重试。预览和实际评分的日期一致（决策 026 第 3 条）
- 日期浮上来是本产品唯一的一处动效，用户设置了减少动效时不播放；刷新后看到的已评的分不播放
- **“下一个”评过分才能点**：评分页的主线是评分后按 Enter。点“下一个”时重新取今天的计划，进入下一个；今天的都学完了回今天页（这一步也会记下“当天完成”）
- **“接着问”学完就能点**，不要求先评分，和后端一致
- 候选知识点（#31）没有数据，先不显示

### 6. 学习模式的顶栏

布局自己取今天的计划，显示分段进度（和今天页共用 `ProgressSegments`），并把计划放进模块级的共享状态 `studyHeader`，页面用它显示“新学 / 复习”和类型标签。“本次 X 分钟”用后端的有效时长，每次回复结束后随会话一起更新，不是前端的秒表：前端计时会把中途离开的时间也算进去，和有效时长的口径不一致。

## 理由

- **以后端为准**：流式过程中的状态（已发、已收、已存）容易和库里不一致；每次结束都重新取一次，刷新、断开、出错之后看到的都和后端一致，代价只是多一次很小的请求
- **自己写渲染器**：模型输出的格式就那几种；自己写的不加依赖，也不用配置净化规则。先转义再识别，从根上排除注入
- **地址按会话 id**：评分页是中转站，用户会在评分页和接着问之间来回、会刷新；按知识点开始的话，刷新就可能新建会话
- **“下一个”要先评分**：评分是学习闭环的最后一步，跳过评分进入下一个，这个知识点就没有复习安排

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 地址按知识点 `/study/:kpId` 一直用到底 | 刷新评分页时会按知识点重新开始，新建会话 |
| EventSource | 只能发 GET，带不上回答和 CSRF 令牌（决策 025） |
| 流式过程中在前端自己维护全部消息 | 断开、出错、刷新后容易和库里不一致 |
| `marked` + `DOMPurify` | 两个依赖，还要配置净化规则；模型输出的格式就那几种 |
| 纯文本显示老师的回复 | 代码块会露出 ``` 符号，列表、加粗都没有层次 |
| 前端计时显示“本次 X 分钟” | 会把中途离开的时间也算进去 |
| “下一个”不评分也能点 | 这个知识点就没有复习安排了 |

## 遗留问题

- 老师的称呼固定为“老师”，设置中的称呼由 #53 加上
- 候选知识点由 #31 加到评分页
- 流式过程中刷新页面，正在生成的那条回复要等生成完、下一次取会话时才显示，期间显示“老师正在回复”
- 渲染器不认引用、链接、图片；出现时原样显示
