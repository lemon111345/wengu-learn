# 035 复习换角度提问

## 背景

PRD 要求“复习时换角度出题，不重复原题”（Must，防止退化成背答案），以及“复习时针对上次没掌握的点提问”。#21 之前，复习和第一次学习用同一套流程和 prompt（v3 开头写的是“第一次学懂一个知识点”）：每次复习都从摸底、讲解重来一遍，问题很可能和上次差不多；评分建议早已存了 `weakPoints`（决策 008、026），却没有用上。

issue 要求在方案中确定：怎么识别“以前问过的问题”。

## 决策

### 1. prompt v4：新增“复习”流程

`prompts/learning-chat-v4.md`。第一次学习的流程不变；第一条消息注明“这是复习”时，代替摸底和讲解：

1. 开场直接提一个问题，不寒暄、不讲解；换一个角度：不重复、也不只是改写以前问过的问题，可以给具体场景让学生判断、问为什么这样设计、问“如果……会怎样”、对比或排查；有“上次没掌握的”时优先围绕其中一点
2. 答对了沿新角度追问 1～2 次；答错或答不出时直接指出、简短讲清楚，再换个问法确认一次，同一个点最多问两次
3. 仍然经过完整作答再收尾：完整作答针对知识点标题中的问题，评分靠它

建议 3～5 次回答。轮数上限、标记、跳过讲解都和第一次学习一样。

### 2. 第一条消息带上以前的学习情况

知识点评过分时（`review_log` 中有记录），在知识点信息后面加一段：

- 以前学过几次（评分次数）、上次的评分
- 上次评分建议中的 `weakPoints`
- 最近 3 次学习会话中老师问过的问题，去重后最多 15 个，留最近的

只放在第一条用户消息里，system prompt 不变（和决策 008 一致）。

### 3. 问过的问题：取每条回复最后的问句

prompt 规定“每次只问一个问题，放在回复的最后”，所以从老师的每条回复中取最后一个问句；同一行中紧挨着的问句一起取（老师常连着问“……会发生什么？为什么要这样设计？”，只取最后一句会只剩“为什么？”）。去掉 Markdown 的加粗和列表符号。带标记的回复（要求完整作答、收尾）不算：它们每次都一样。

### 4. 每轮重新算，不存库

第一条消息本来就不存库、每轮由学习材料现拼。复习信息也一样：只看这次之前的会话（新会话只在上一个评过分后才开），算出来每轮都相同。每轮多几次查询（评分记录、至多 3 个会话的消息、一条评分建议），可以忽略。

## 实验

`ReviewAngleExperiment`（test 目录，`spring-boot:test-run` 运行，DeepSeek deepseek-flash）。用 #14 第二轮作者亲自学的 5 份真实对话作为“上次的学习”，它们的“还没掌握的点”作为 `weakPoints`：

- **开场**：每个知识点用 v4 生成 3 次复习开场
- **全程**：2 个知识点由模型扮演“记得不牢的学生”走完整段复习

第一次运行发现问句提取的问题：只取最后一句时，连着问的两句只剩“为什么？”“快还是慢，为什么？”这样的碎片。改为同一行中紧挨着的问句一起取后重跑（`data-private/experiments/review-20261103-192256-deepseek-flash`）：

| 项目 | 结果 |
| --- | --- |
| 提取的问题 | 5 个知识点共 29 个，都是带场景的完整问题；没有碎片，要求完整作答的回复没有混进来 |
| 开场原样重复以前的问题 | 0 / 15 |
| 开场围绕“上次没掌握的” | 15 / 15 |
| 开场用具体场景、代码或“判断一句说法” | 14 / 15（另一次是“按步骤讲一遍流程”，接近复述） |
| 只是把旧问题包一层场景（踩线） | 1～2 / 15 |
| 全程 | 两次都直接从新角度开场，答错才讲，经过完整作答后收尾；学生回答 5 次 |

## 理由

- **复习先让学生自己说**：主动回忆比再听一遍讲解更能巩固记忆，也正是“防止退化成背答案”的意思；讲解只在答错时补
- **完整作答保留**：评分建议以完整作答为主要依据（决策 008），复习和第一次学习的评分标准一致
- **取最后的问句**：利用 prompt 已有的格式约定，不额外调用模型、不改输出格式，旧会话也能直接用；纯函数，便于测试
- **`weakPoints` 一起做**：和问过的问题放在同一处，几乎不增加代码，文档早就把它分给了 #21

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 把以前老师的整条回复都传给模型 | 第一条消息会很长，讲解内容会干扰模型判断“问过什么” |
| 让模型用标记写出问题，或在评分建议中多输出“问过的问题” | 要改输出格式；旧会话没有；评分建议失败时也拿不到 |
| 只在第一条消息中附上历史、流程不变 | 复习仍然从摸底和讲解开始，等于重新学一遍 |
| 会话开始时把复习信息存进新列 | 要一次迁移；重新计算的结果本来就是稳定的 |

## 遗留问题

- **第二次复习还没验证**：实验只模拟了第一次复习。issue 的完成标准（3～5 个知识点各复习两次、人工检查问题与上次不同）由作者在每天自用中验收
- 同一个知识点生成几次开场，有时几次都差不多（实验中 MySQL 隔离级别那题）。下一次复习时这次的问题会进入“以前问过的”，预计会换掉；自用中再观察
- 合并的知识点只看主知识点自己的会话：被合并的知识点的学习记录留在原处（决策 029），它们问过的问题不会带上
- 实验中的 `weakPoints` 来自 #14 时期的评分 prompt，每条很长、写成问题；评分 v3 的输出更短，效果待自用中观察
