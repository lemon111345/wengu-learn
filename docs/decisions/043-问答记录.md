# 043 问答记录

## 背景

自用中发现（#103）：经常用“接着问”，问到一半去干别的事，之后想重读或继续问很麻烦。要走“知识库 → 找到知识点 → 学习记录 → 点开 → 翻过整段学习对话”，而且回顾页只读，想继续问还得绕回评分页。

要定的是：页面放在哪、“继续问”和 #82 的只读规则怎么协调、数据从哪里来、隔天继续问的时长怎么算、知识点今天要复习时怎么办。

## 决策

### 1. 新增“问答记录”页，做成 AI 对话的样子

- 导航放在知识库下面，地址是 `/questions` 和 `/questions/:id`，id 是学习会话
- 左栏按最近活动列出接着问的对话，右栏是问题目录、对话和输入框
- 问题目录是学生问题的原话，由前端从消息里取，不调用模型
- 这个页面在应用框架内。评分页进入的接着问仍然是专注模式，两边是同一场对话

### 2. 回顾页保持只读，增加跳到这里的入口

#82 定下的“只读，打开页面不调用模型，也不新建接着问的会话”不变。继续问放在新页面：回顾页前面是评分和整段学习对话，不适合聊天。

问答记录也遵守这一点：打开页面不建会话，没问过的学习记录在第一次发送时才调用 `POST /api/sessions/{id}/follow-up`。

### 3. 接口

- `GET /api/follow-ups?keyword=`：对话列表，没有提问的空对话不返回
- `GET /api/sessions/{id}/follow-up-status`：单条对话的状态，只查不建。回顾页跳过来时，这条对话可能还不在列表里
- 对话本身沿用 `GET /api/sessions/{id}` 和流式接口

能不能继续问、为什么不能，都由后端判断，客户端只负责显示（决策 034）。

### 4. 搜索在后端读出消息后按文字过滤

范围是知识点标题、学生的问题和老师的回答，不区分大小写。标题在 knowledge 模块，SQL 不能跨模块查；接着问的数据量很小，数据多了再改。

### 5. 隔天继续问的时长仍算在第一次接着问的那天

时长记在会话上，按会话开始的时间统计，隔天继续问时，今天和本周会少算。要算准得新增按天记录时长的表，第一版接受这个偏差。

### 6. 知识点今天要复习时，提示但不拦

显示“今天要复习这个知识点，建议复习后再看”，已有的对话默认折叠，点开就能看。先看答案再去复习，评分会偏高，后面的复习间隔也会跟着变长；但完全拦住会妨碍查资料。暂停的知识点不算要复习。

## 理由

- **沿用接着问的会话**：不用新的对话模型，评分页和问答记录看到的是同一场对话
- **单独的状态接口**：加进 `SessionView` 的话，每次读会话都要多查几次，而只有这个页面用得上

## 代价

- 同一知识点的多次接着问各占一行，标题相同，靠日期和最后一问区分
- 一次学习只有一场接着问，上限 30 问仍然保留，问满后只能查看

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 直接在回顾页加输入框 | 回顾页前面是评分和整段学习对话，不适合聊天 |
| 把状态加进 `SessionView` | 每次读会话都多查，只有这个页面用得上 |
| SQL `LIKE` 搜索 | 标题在 knowledge 模块，SQL 不能跨模块查 |
| AI 总结、主题整理 | 要调用模型，问了新问题还得重算，也可能归纳错 |
| 按知识点直接开始接着问 | 要改“一次学习一场接着问”的模型，和 #54 一起考虑 |
| 按天记录学习时长 | 为这点偏差新增一张表，不值得 |
| 知识点要复习时禁止查看 | 会妨碍查资料 |

## 遗留问题

- 复习时带回接着问过的问题：要改学习对话的 prompt，需要先做实验
- 候选知识点 #31 的触发方式：这个页面没有“返回”的时刻，做 #31 时再定
