# 007 M1 范围与设计调整

## 背景

M0 完成后（见 [M0 复盘](../retros/M0.md)）规划 M1。按 PRD，M1 要实现全部 Must 功能，形成“导入 → 每日计划 → 学习对话 → 评分调度”的自部署闭环。规划时发现，原计划中有几处和 M0 的结论、作者的实际情况不匹配：

- M0 只验证了面试题文本的抽取，源码抽取没有验证；结合源码追问属于 M2
- 模型配置如果做成设置页，Key 就要存进数据库，而加密存储属于 M3
- 前端需要作者从零学起，原来估计的 2～3 周不够
- SYSTEM_DESIGN 已经确定 M1 不进入每日计划，EXPERIENCE 类型的学习方式是“结合用户源码追问”，M1 没有源码，同样无法学习

## 决策

1. **M1 的模型配置只用环境变量**（`WENGU_LLM_*`，通过 .env 提供），不做设置页，不把 Key 存进数据库。model_config 表和 Key 加密存储仍属于 M3
2. **源码导入移到 M2**，和“复习时结合用户源码追问”一起做。M1 的导入只支持面试题文本和文档（PDF / Markdown / DOCX）
3. **M1 中 EXPERIENCE 类型和 SYSTEM_DESIGN 一样**，不初始化 card_state、不进入每日计划；抽取时照常标记类型。M2 有了源码导入后再启用
4. **接口设计不在 M1 开工前一次定完**：每个 issue 的方案中定自己的接口，完成后汇总进技术方案
5. **M1 工期调整为约 4～5 周**。阶段 D（前端计划页和对话页，#23）完成后作者开始每天自用，M2 的“连续自用 14 天”从这时开始算

## 理由

- **环境变量够用**：M1 是单用户自部署，使用者就是部署者，改 .env 和改设置页效果一样。Spring AI 已经通过 `WENGU_LLM_*` 读取配置（决策 004），不需要新代码
- **源码导入和源码追问是一体的**：只导入不追问，导入的源码在 M1 中没有用处；源码的抽取粒度也没有验证过，放在 M1 会拖慢闭环
- **EXPERIENCE 不进计划**：没有源码，模型只能泛泛地问“你项目里怎么做的”，无法检验，评分也没有意义。类型照常标记，M2 启用时不需要重新抽取
- **接口随 issue 确定**：实现之前不了解细节，提前定的接口大概率要改；每个 issue 只定自己用到的接口，改动范围小
- **工期按实际调整**：前端从零学起是已知的额外成本；自用提前开始，可以让 M2 的 14 天和 M1 后半段（补全功能）并行

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| M1 做模型设置页，Key 存进数据库 | 要先实现加密存储，这是 M3 的工作；明文存储违反 PRD 的 Key 安全约束 |
| 源码导入留在 M1 | 源码抽取没有验证；结合源码追问在 M2，导入了也用不上 |
| EXPERIENCE 在 M1 中用通用 prompt 学习 | 没有源码时问不出有效的问题，反而产生无意义的评分记录 |
| 开工前一次定完所有接口 | 实现前不了解细节，定了也要反复改 |
| 维持 2～3 周 | 前端需要从零学起，按原工期会压缩学习和审查的时间 |
