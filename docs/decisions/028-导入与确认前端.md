# 028 导入与确认前端

## 背景

#22 做导入资料（ui.md 5.7）和确认知识点（ui.md 5.8）两个页面，把“粘贴面试题 → 识别题目 → 勾选 → 抽取 → 确认 → 加入每日计划”在浏览器里走通。后端的导入、抽取、重试、确认接口已经在 #14～#17 完成（决策 011～015）。要定的是：

- 导入的三步和确认页的地址怎么设计，抽取要一两分钟，刷新、离开后怎么回来
- 抽取进度怎么显示，剩余时间怎么估
- 有的批次失败时怎么重试
- 有的题没拆出知识点时，“单独再抽这 N 道”和当前这份草稿是什么关系
- 漏题的批次在后端被判为失败，确认页的漏题提示永远出不来（决策 014 的校验规则）

## 决策

### 1. 地址：前两步在页面内存中，开始抽取后按草稿 id

| 路由 | 作用 |
| --- | --- |
| `/import` | 第 1 步粘贴原文、识别题目；第 2 步勾选题目、开始抽取 |
| `/drafts/:id` | 按草稿的状态显示：抽取中、失败时是第 3 步（抽取进度）；等你确认时是确认知识点；已确认时是结果摘要 |

- 前两步只在页面内存中。识别完题目后刷新，要重新识别一次；这一步只有几十秒，不值得为它存状态
- 开始抽取后用 `router.replace` 换成 `/drafts/:id`：草稿存在库里，刷新、离开后再回来都能接着看。今天页的“等你确认”、导入页右侧的“最近导入”都链接到这里
- 这次打开时看的是进度，抽完后停在进度页，点“查看结果”再进入确认（ui.md 5.7）；直接打开一份已经抽完的草稿，进入确认页
- 抽取中每 3 秒取一次草稿（决策 013：进度几十秒才变一次，轮询就够）

### 2. 进度：每批一个进度块，剩余时间按每道题 4 秒估

- 每批显示题号范围（连续时写“第 1～30 题”，否则写“30 道题”）和状态：完成（抽出几个知识点）、正在抽取、排队中、没抽出来
- 正在抽取的批次不知道进度，显示来回移动的一段；用户设置了减少动效时静止
- 剩余时间 = 还没完成的批次的题数 × 4 秒，向上取整到分钟，至少 1 分钟。30 题一批约 2 分钟，和决策 013 实测的“1～3 分钟”一致；批次按顺序执行，所以直接相加
- 一批抽出的知识点数按条目的第一个来源题号归到批次：条目不会跨批

### 3. 重试：一个按钮重试全部失败的批次

所有批次都结束、有失败的时，显示“重试失败的批次（N 批）”，调用 `POST /api/drafts/{id}/retry`。后端本来就是一次重试全部失败的批次（决策 013），已经抽出来的保留。

### 4. 确认知识点

- 按学习顺序列出；**只能取消勾选，不能修改**（ui.md 5.8），草稿保持模型的原始输出，修改在知识库中进行
- 右侧栏：将加入的数量、按类型的数量、“按每天新学 X 个，大约 Y 天学完这一批”。天数只算能学的类型，系统设计、个人经历只收录（决策 007），不进每日计划
- “确认加入 Ctrl Enter”后回到今天页，提示“已加入 N 个知识点”
- 已确认的草稿显示同一个列表，复选框禁用，没加入的条目变淡并写“没有加入”

### 5. “单独再抽这 N 道”另起一份草稿

按钮用这几道题的题号调用 `POST /api/drafts`，跳到新草稿的进度页；**当前这份草稿不动，之后照样确认**。

新草稿抽取时，当前草稿的条目还没确认、不在去重上下文中（决策 014 只用已有知识点和同一草稿的其他批次），模型可能抽出和当前草稿重复的知识点。用户会在新草稿的确认页看到，不想要的去掉勾选就行。

### 6. 只剩漏题时，最后一次尝试算成功

决策 014 的校验要求每道题都有新知识点或写进 covered，漏了题的批次会重试，两次都漏就失败。这样一来，漏题的批次整批作废，确认页的漏题提示也永远出不来。

改成：**最后一次尝试时，如果校验问题只有“漏题”这一条，这一批照样算成功**；漏题的说明留在 `batch.error`，记一条警告日志。前两次尝试仍然按原来的规则重试，给模型改正的机会。其他问题（题号不存在、标题和已有重复等）照样失败。

后端为此补了两处：

- `DraftView` 增加 `sourceName`（确认页的说明要写来源），和 `uncovered: [{questionId, text}]`：成功批次的题，减去条目引用的、减去 covered 中的
- `ExtractionValidator.onlyMissing` 判断校验问题是否只有漏题

## 理由

- **按草稿 id**：抽取要一两分钟，用户很可能离开再回来；草稿本来就在库里，地址对上它，刷新、从别的页面进来都不用另外恢复
- **前两步不存**：识别只要几十秒，存下来要多一张表或多一个状态，收益很小
- **4 秒一道题**：剩余时间只要大致可信，用实测数据的常量就够；按已用时间推算，第一批还没完成时没有数据
- **另起一份草稿**：两份草稿各自完整，确认、重试的逻辑不用改；合进当前草稿要处理“草稿已经 READY 又多出一批”的状态，确认页也要等它
- **漏题不拖垮整批**：一两道题漏了，其余几十个知识点一起作废，代价太大；用户在确认页看到漏了哪几道，可以单独再抽

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 三步都在 `/import`，进度用查询参数 | 进度是草稿的状态，放在导入页的地址上，从今天页进来还要拼参数 |
| 识别结果存进 source，第 2 步也能刷新恢复 | 多一个状态，识别只要几十秒 |
| 按已用时间推算剩余时间 | 第一批完成前没有数据，估出来的数还会跳 |
| 每个失败的批次单独一个重试按钮 | 后端一次重试全部失败的批次，分开按没有意义 |
| “单独再抽”合进当前草稿 | 要处理已经 READY 的草稿多出一批，确认页要等它抽完 |
| 漏题时整批失败（原规则） | 漏一两道题，其余的都作废；确认页的漏题提示永远出不来 |
| 漏题时第一次就算成功 | 不给模型改正的机会，漏题会变多 |
