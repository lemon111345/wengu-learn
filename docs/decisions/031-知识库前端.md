# 031 知识库前端

## 背景

#51 按 ui.md 5.9 实现知识库页面：筛选、排序、列表、右侧详情、批量操作、删除后撤销、合并弹窗、搜索，以及空状态。接口在 #25（决策 029）、#50（决策 030）已经做好。要定的是：

- 筛选和排序在前端做还是交给后端
- 搜索的形式：ui.md 5.9 画的是顶栏搜索框，第 7 节写的是居中弹窗，第 6 节写“M1 可以先在前端过滤知识点列表”
- 编辑到一半切换知识点怎么办
- 删除后的撤销提示放在哪里、留多久
- 截图与规范的出入怎么处理

## 决策

### 1. 筛选和排序交给后端，搜索在前端

- 切换掌握程度、类型、排序时，带上参数重新取 `GET /api/knowledge-points`。各掌握程度的数量、排序规则（待学、暂停、只收录总在最后）都由后端算，前端不再写一遍
- 连续切换时只用最后一次请求的结果，先发后到的旧结果丢掉
- 筛选状态只在页面中，不写进地址；刷新后回到“全部”
- 任何操作（保存、暂停、删除、撤销、合并）完成后都重新取列表，必要时重新取详情，不做乐观更新（决策 029 的约定）

### 2. 搜索：知识库顶栏的搜索框（方案 A）

- 顶栏搜索框在前端按标题过滤当前列表，不区分大小写，叠加在两种筛选之上；“清除筛选”时一起清空
- Ctrl+K：在知识库中聚焦搜索框；在其他页面跳到知识库（带 `?search`，打开后聚焦并去掉）
- 第 7 节的居中搜索弹窗留到需要全局搜索时再做

### 3. 选中与编辑

- 默认选中第一行；重新取列表后，原来选中的还在就保持，否则选中第一行
- 标题、类型、要点先改在本地副本上，“保存修改”时只提交改了的字段（PATCH）；比较时忽略首尾空白，和后端保存时一致
- “AI 生成 / 你改过”按编辑框当前的内容实时判断；“恢复 AI 版本”只把原文填回编辑框，保存后才生效。不是从草稿来的知识点不显示这个胶囊
- **有没保存的修改时**，切换知识点或离开页面先确认“放弃修改？”；重新取列表时如果选中的不在列表中，也不自动换，免得筛选一下修改就没了

### 4. 删除与撤销

- 详情中的删除和批量删除都直接执行，底部出现“已删除 / 已删除 N 个知识点 撤销”，停留 6 秒；有撤销就不再弹确认框
- 提示条是自己写的小组件（`UndoToast`），不用 ElMessage：ElMessage 显示在顶部，里面放按钮要拼 VNode
- 撤销后选中删除的那一个

### 5. 批量操作与合并

- 勾选保存为 id → 标题，切换筛选后保留：合并弹窗要显示不在当前列表中的标题
- 合并弹窗用单选选主知识点，默认第一个，写明“合并后不能撤销”，弹窗本身就是确认；合并后打开主知识点
- 批量只有“暂停复习”，恢复在详情中逐个操作（ui.md 5.9）

### 6. 文案和截图的出入

以 ui.md 为准：

- 截图的“暂不支持”写成“只收录”
- “下次复习”一列：学过的显示日期；明天到期显示“明天”，已经到期（days ≤ 0）显示“今天”，两者都用 `--wg-warn`；待学“等待学习”、暂停“已暂停”、只收录“以后支持”（文案取自 mockup）
- 详情顶部只有学过的才显示“下次复习：X”（同 mockup）
- 学习记录“10月30日 新学，良好（AI 建议：良好）”，没有 AI 建议时去掉括号；并进来的记录下面加一行“合并自：<标题>”

### 7. 组件划分

`views/library/` 下：`LibraryView`（页面状态）、`LibraryFilters`、`KnowledgeTable`、`DetailPanel`、`MergeDialog`、`UndoToast`、`MasteryDot`、`format.ts`（文案）。色点只有知识库用，先放在这里，统计页需要时再移到 `components/`。

## 理由

- **交给后端**：排序规则和数量统计已经在后端有测试（决策 030），前端再写一遍会有两份规则
- **搜索框而不是弹窗**：M1 只有知识库需要搜索，前端过滤的搜索框代码最少，和 5.9 的截图一致
- **保护没保存的修改**：要点是评分的标准，改一段要点花的时间不短，一次误点就丢掉代价太大
- **撤销代替确认**：误删的代价由撤销兜底，每次删除都弹确认框会打断操作

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 一次取全部、在前端筛选排序 | 排序和数量的规则要在前端再写一遍 |
| 筛选写进地址（`?mastery=`） | M1 没有分享和回退到某个筛选的需要，多一层同步 |
| 全局居中搜索弹窗（方案 B） | 多一个弹窗组件，还要支持按地址定位知识点；M1 用不上 |
| 切换时静默丢掉修改 | 容易丢掉改了很久的要点 |
| 删除前弹确认框 | 有撤销就够了，确认框打断操作 |
| 用 ElMessage 做撤销提示 | 位置在顶部，不符合 ui.md 的“底部提示” |
| 乐观更新 | 本地接口很快，重新取一次最简单，也保证以后端为准 |

## 遗留问题

- 表格行之间不能用上下方向键移动，用 Tab 和 Enter 操作
- 筛选不在地址中，刷新后回到“全部”
