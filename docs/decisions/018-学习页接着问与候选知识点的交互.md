# 018 学习页、接着问与候选知识点的交互

## 背景

决策 008 定下了学习对话的结构（摸底 → 讲解 → 检验 → 追问 → 完整作答 → 收尾），以及“接着问”和“候选知识点”两个功能。设计前端页面（`docs/design/ui.md` 5.3～5.6）时，要回答这些问题：学习时显示什么进度；完整作答时怎么防止学生照着上面的对话抄；已经会的知识点怎么快速过；评分、接着问、候选知识点之间怎么跳转；没有现成题目时怎么学。

候选知识点从对话中怎么提炼，单独写在决策 019。

## 决策

### 1. 学习页

- **不显示学习阶段的进度**（摸底、讲解……）：模型无法可靠地报告自己处在哪个阶段
- **学习对话 prompt 在要求完整作答时输出【完整作答】标记**，和【学习结束】是同一机制。前端据此把输入框的标签换成“完整作答：不看上面，把整个问题讲一遍”，并折叠上面的对话；提交后恢复显示
- **新增“这个我会，直接完整作答”**：跳过讲解，直接进入完整作答，照常评分。会话上记录“跳过了讲解”
- **不做“标为熟知、不再复习”**。确实不想复习的，用知识库里的“暂停复习”

### 2. 评分页

- **评分按钮不预先选中 AI 建议**，只在建议的那一个下面标“AI 建议”
- **评分页是每个知识点的中转站**：主线是评分后按 Enter 进入下一个；支线是进入接着问，问完按 Esc 回到评分页

### 3. 接着问

- 从评分页进入，问完返回评分页
- **不显示剩余次数**。后端保留一个较高的、不显示的上限，接近时老师温和提示可以先回去，把聊到的新知识加入复习

### 4. 候选知识点

- **统一在评分页确认**，来源包括评分建议中的 `outOfScopeGaps` 和接着问的对话，两者去重
- 不确认的保留在今天页的“等你确认”里，在确认知识点页面处理，来源写“接着问：<原知识点标题>”
- 模型认为不值得加入的也返回给前端，折叠显示并附原因，用户可以手动勾选。**模型的判断只决定默认是否勾选**
- 记录用户最终勾选和取消的条目

### 5. 从一个问题开始

- 用户在今天页输入一个问题，不依附于已有知识点，以接着问的方式学习，结束时整理成候选知识点。复用接着问与候选知识点的机制，页面复用接着问
- M1 末有余力就实现，否则放到 M2 开头。但 `study_session` 的会话类型字段（学习知识点 / 接着问 / 从一个问题开始）现在就要加，“从一个问题开始”的会话不关联知识点

## 理由

- **不显示阶段**：阶段由模型自己判断，进度条会出现倒退、跳步或停在某一步不动；显示一个不可靠的进度，比不显示更糟
- **折叠对话**：完整作答是唯一可靠的检验（决策 008），对话就在上面时，学生很容易照着抄，检验就失效了。标记沿用【学习结束】的做法，前端不用猜模型的意图
- **“直接完整作答”而不是“标为熟知”**：决策 008 的实验已经发现，“觉得会”和“能讲出来”是两回事。直接完整作答既省掉了讲解的时间，又保留了检验；评分照常进入调度，真会的自然间隔拉长
- **不预选 AI 建议**：评分以用户确认的为准（技术方案“关键设计决策”），预选之后按一下 Enter 就是接受，用户确认就成了形式，AI 建议的准确度也没法评估
- **评分页做中转站**：评分是一个知识点的终点，接着问是可选的支线。从评分页出发、回到评分页，用户始终知道“下一个”在哪里；候选知识点也有一个固定的确认位置
- **不显示剩余次数**：上限只是防失控的保险（决策 008 第 4 条），显示出来会让人觉得被限额，或者为了用完次数而问
- **候选知识点只决定默认勾选**：模型的过滤会出错（决策 008 的已知问题：`outOfScopeGaps` 偶尔把要点内的内容算进来），用户必须能看到并推翻它
- **从一个问题开始复用接着问**：从问题倒推着学（PRD“学习原则”）本来就是接着问的形态，只是起点不是已有的知识点。会话类型字段现在加，以后实现时不用改会话的表结构和查询

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 学习页顶部显示阶段进度条 | 模型无法可靠地报告阶段 |
| 完整作答时对话照常显示 | 学生会照着抄，完整作答失去检验的作用 |
| “标为熟知、不再复习” | “觉得会”不等于“能讲出来”；不想复习的用“暂停复习” |
| 评分按钮预先选中 AI 建议 | 用户确认变成形式；无法评估 AI 建议的准确度 |
| 接着问显示剩余次数 | 上限只防失控，不是额度 |
| 只显示模型建议加入的候选 | 模型的过滤会出错，用户看不到就无法纠正 |
| 从一个问题开始时先生成知识点再学 | 用户还不知道要学的内容怎么拆，先学再整理更自然 |
