# 019 候选知识点的提炼方式

## 背景

决策 008 定下：学完一个知识点后，把评分建议的 `outOfScopeGaps` 和接着问中聊到的新内容整理成候选知识点，复用草稿表和确认流程。交互见决策 018。还没定的是：怎么从一段对话得到粒度合格、带要点、类型正确、和已有知识点不重复的知识点。

现有的抽取（决策 005、006、014）输入的是题目，已经解决了粒度、类型判断和去重；对话和题目的区别在于，对话里混着闲聊、学生的错误说法和原知识点范围内的内容。

## 决策

1. **不新建抽取流程**：新增“整理成题目”一步，把对话整理成题目，再走现有的抽取（v5 规则、类型判断、决策 014 的去重上下文），写入草稿，复用确认流程（决策 015）
2. **“整理成题目”的输出**，每道题包括：
   - 规范化后的问题
   - 出自对话的哪几轮。写要点时只依据这些轮次中老师讲过的内容
   - 是否建议加入，以及原因：对话本身的话、在原知识点要点范围内、过于细碎
3. **不建议加入的也返回给前端**，折叠显示并附原因，用户可以手动勾选。模型的判断只决定默认是否勾选
4. **记录用户最终勾选和取消的条目**（草稿条目已有 decision 字段，决策 015）
5. **整理时机**：接着问结束时在后台执行一次，不边聊边整理
6. **prompt 中“面试”这一学习方向集中写在一个变量里**，便于以后扩展到其他学习方向（PRD“学习原则”）
7. **实现前先做小实验**：约 10 次真实的接着问对话，人工标注愿意勾选的比例，以及被过滤掉的题中有没有想要的。结论补进本记录

草稿的来源怎么记、“是否建议加入”存在哪一层（它是题目级的判断，草稿条目是知识点级的）、和 `outOfScopeGaps` 怎么去重，在候选知识点 issue（#31）的方案中定。

## 理由

- **复用抽取**：粒度标准、类型判断、去重规则都在 M0 和 #16 中验证过，只在一处维护。另起一套从对话直接抽知识点的 prompt，这些规则要再写一遍、再验证一遍，以后改一处还要记得改另一处
- **分成两步**：“对话 → 题目”和“题目 → 知识点”是两件事。分开后每一步都能单独检查，和题目切分与抽取分开（决策 011）是同样的思路。题目也是用户最容易判断“要不要学”的形式
- **限定出处的轮次**：对话里有学生的错误说法，也有老师顺带一提、没有展开的内容。要点只依据指定轮次中老师讲过的话，避免把错误或没讲过的内容写进评分标准
- **三种不建议的原因**，对应三种常见的噪音：
  - 对话本身的话：如“再举个例子”，不是知识
  - 原知识点要点范围内：已经由原知识点的复习覆盖，再加就是重复
  - 过于细碎：一次性的好奇，如具体的参数值、冷门的版本细节，不值得间隔复习
- **结束时整理一次**：边聊边整理，每一轮都要多调用一次模型；问题还没问完时，整理出的题目也不准
- **先做实验**：整理的效果决定这个功能有没有用。愿意勾选的比例太低，说明整理出的大多是噪音；被过滤掉的题里有想要的，说明过滤太严

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 新写一个从对话直接抽知识点的 prompt | 粒度、类型、去重的规则要再写一遍、再验证一遍 |
| 边聊边整理 | 每轮多一次调用；问题没问完时整理不准 |
| 只返回建议加入的题 | 模型的过滤会出错，用户无法纠正（决策 018） |
| 要点依据整段对话来写 | 会把学生的错误说法和老师没展开的内容写进评分标准 |
