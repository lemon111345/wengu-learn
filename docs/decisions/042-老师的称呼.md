# 042 老师的称呼

## 背景

用户可以给老师换个称呼（#53），只改变显示名称和模型的自称，讲解方式不变。要定的是：称呼存在哪、怎么告诉模型、界面怎么拿到、设置页什么时候保存。

## 决策

### 1. 存在 `user_settings.teacher_name`

- 迁移 V14 新增 `teacher_name VARCHAR(20) NOT NULL DEFAULT '老师'`，已有用户自动得到默认值
- 由 `UserSettingsService` 校验：去掉首尾空格，最多 10 个字，不能有换行等控制字符，否则返回 400
- 清空时恢复成“老师”，不报错：设置页是自动保存的，清空输入框不该算填错

### 2. prompt 文件不动，称呼不是默认值时在末尾追加一句

追加的内容是：“学生称呼你为‘X’，需要自称时用这个称呼，讲解方式和规则都不变。”学习对话和接着问都用，每次回复时读取，改了马上生效。

issue 原来写的是“把 prompt 中的自称改为变量”，实现时改成了追加：

- prompt 第一句“辅导老师”是角色定义，不是自称，换成变量会变成“辅导小明”
- 默认称呼时发给模型的内容一个字都不变，学习对话 v4 的实验结果仍然有效，不用发新版本
- `prompt_version` 仍记 v4 和 v1：追加的一句不改变教学规则

评分建议的 prompt 和对话记录中的“【老师】”是给模型看的角色标签，不改。

### 3. 界面从 `SessionView.teacherName` 取

学习页、收尾页、接着问和回顾页本来就要取会话，增加一个字段就够了。历史对话也显示当前的称呼，不保存当时的称呼：它只是显示名称。

后端少数报错文案（如“老师还在回复，请稍等”）保持原样，很少出现，为此在错误路径上读设置不值得。

### 4. 设置页在输入框失焦或按 Enter 时保存

## 理由

- **放在 `user_settings`**：它就是一项用户设置，读写接口已经有了
- **校验放后端**：称呼会进系统提示，长度和控制字符的限制不能靠客户端

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| prompt 中的“老师”换成变量，发布新版本 | 改的是角色定义；默认称呼也要重新验证 prompt |
| 前端单独取设置并缓存 | 多一个请求，改完称呼后缓存可能过期 |
| 像“每天学几个”那样停手 500 毫秒保存 | 打字中途清空时，会把“老师”填回输入框，打断输入 |
| 保存每次对话当时的称呼 | 只是显示名称，不值得多一份数据 |
