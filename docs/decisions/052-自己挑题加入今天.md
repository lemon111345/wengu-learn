# 052 自己挑题加入今天

## 背景

作者自用时（2026-11-19）遇到两个不方便的地方（#128）：

1. **只能一道一道地挑。** 知识库详情里的“开始学”（#81）只能学当前这一道，想挑一批今天学，没有入口。
2. **中途退出后不好找回来。** 从知识库开始学、学到一半退出的题，不在今天页上，下次只能回知识库在两百多道里找。

会话这一层其实已经能接着学：同一个知识点最近的会话还没走完时，开始学习会返回那个会话（决策 025、#23）。缺的只是让这道题出现在今天页上。

作者已经定了方向：加入的题直接进今天页的“新学”列表，不单独分组，算今天新学的；总数超过“每天学几个”时如实显示和统计。

要定的是：加入的题和计划派发的题怎么分名额，存在哪，第二天还在不在，哪些题能加入，以及和“当天完成”（决策 041）怎么配合。

## 决策

### 1. 新学列表由三部分组成，都占每天学几个的名额

今天页的新学列表依次是：

1. **学到一半的**：待学的知识点中有学习会话的，按学习顺序。待学的知识点一评分 `last_review` 就有值、不再是待学，所以“待学并且有学习会话”就是学到一半（包括学完还没评分的）。不另外存储，plan 向 chat 查询
2. **今天加入的**：今天从知识库加入、还是待学的，按加入的先后
3. **计划派发的**：其余待学知识点按学习顺序，补足剩下的名额

同一个知识点只出现一次，排在最靠前的那一部分。

名额的算法改为：

> 剩余名额 = max(0, 每天学几个 − |还没完成的到期复习 ∪ 今天评过分的 ∪ 学到一半的 ∪ 今天加入还没学的|)

也就是**挤占**：加入的题先用今天剩下的名额，派发的只补空位。加入的比剩余名额多时，全部照样显示，新学数会超过设置值，概况面板照实显示。例：每天 7 个、没有复习，加 3 道，新学是 3 + 4 = 7；加 10 道，新学就是 10。

### 2. 加入只当天有效，开始学了的留到学完

- 加入记录带学习日，只在那一天算“今天加入的”。第二天没开始学的回到待学队列，按原来的学习顺序排
- 开始学了、没学完的，按第 1 条的“学到一半的”一直留在新学列表的最前面，直到评分。从详情点“开始学”的题（#81）也一样，不需要先加入今天

### 3. 加入记录存在 plan 的小表 `plan_pick`

字段：id、user_id、kp_id、study_date（学习日）、created_at；(user_id, study_date, kp_id) 唯一，同一天重复加入由唯一索引挡住。迁移 V19。

这张表只记“用户哪天把哪道题加进了今天”这个**意图**，不是计划的快照：计划仍然每次实时计算，“每日计划不建表”的原则不变。和“当天完成”（决策 020）一样，存的是算不出来的事实。

### 4. 只有待学的能加入

接口 `POST /api/plan/today/picks {kpIds}`，返回 `{added, alreadyInToday, skipped}` 三个数：

| 情况 | 处理 |
| --- | --- |
| 待学（没学过、没暂停、没删除、参与调度） | 加入，算 added |
| 已经在今天的新学列表里（三部分中的任意一部分） | 不重复写，算 alreadyInToday |
| 学过的（包括还没到期的） | 不加入，算 skipped。等于提前复习，会打乱 FSRS 安排的间隔；到期的本来就在今天的复习列表里 |
| 暂停的、只收录的、删除的、不存在或不属于当前用户的 | 不加入，算 skipped |

没有选择时 400。批量操作不因为混进了不能加入的就整批失败：知识库的勾选里经常混着学过的，让用户先筛掉再点太麻烦。

### 5. 加入的题算今天的任务

加入的题没学完，今天就不算学完。“当天完成”的判断（计划变空、今天学过）不用改。

## 理由

- **挤占和 #81 的口径一致**：从知识库学完一道本来就占名额、少派一道。“加入今天”的意思是“今天学这几道”，不是“今天多学几道”，挑题不会让每天学完变难，对 M2 关卡（连续 7 天学完）也没有额外压力
- **学到一半的从会话推出来，不另存**：事实已经在 study_session 和 card_state 里，再存一份会不同步；还顺带解决了 #81 单道开始学的题退出后找不到的问题
- **没开始的只留当天**：一次挑了很多、没学完时，不会以后每天都被占满、学不完、连续天数断掉；真想学的第二天再加一次即可
- **加入的题算任务**：在挤占的口径下，加入的题占了派发的名额，如果又不算任务，挑满名额后只学一道也能算“学完”

## 放弃的方案

- **叠加：加入的题不占名额，派发照旧**：每次挑题今天都会变多，和 #81 单道开始学的挤占口径不一致
- **不建表，把选中的题挪到待学顺序最前面**（复用 sort_order，像 #77 打乱）：没有新表，但超出剩余名额的部分今天看不到，和“如实显示”冲突；原来的学习顺序被改掉，不能恢复
- **加入的题一直留到学完**：一次加太多时，以后每天都学不完
- **开始学了的也只留当天**：解决不了“中途退出后找不回来”，这是 #128 的两个问题之一
- **单独的“自选”分组**：作者已定不做，今天页的列表已经有新学、复习两个，再分一组没有必要
- **学过的也能加入（提前复习）**：FSRS 支持提前复习，但会让间隔变短、稳定性涨得少；作者要的是挑新题，提前复习以后真有需要再单独讨论

## 影响

- plan → chat 多一处调用（查询哪些待学知识点有学习会话），依赖方向不变（决策 002 修订记录）
- 上线后，以前从知识库开始学、没学完的题会一起出现在今天的新学列表里

## 不做

- 从今天移出加入的题：只当天有效，第二天自然消失
- “学到一半”的标签：列表里不区分来源，以后觉得需要再加
- 按技能或类型自动挑题（技能体系在 M3）
