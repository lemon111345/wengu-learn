# 045 提示词超过上下文时明确提示

## 背景

决策 032 记录过：Ollama 的 OpenAI 兼容接口在提示词超过上下文时不报错，只是悄悄截断，用户看到的是“输出不符合要求”。当时估计一批 30 道题很可能超过 16384，另开 #68 处理。

要定的是：一批的题数要不要调整，截断时怎么让用户知道原因。

明确不做：改用 Ollama 原生接口（决策 032）、调整云端模型的批次。

## 实测

模型 `qwen2.5:7b`，上下文 16384。

| 场景 | 结果 |
| --- | --- |
| 30 道题，没有已有知识点，真实流程 | 提示词 4744 + 输出 3042 token，58 秒，抽取成功 |
| 提示词加上已有知识点标题，每个标题约 17.5 token | 约 700 个时提示词 16259，仍然完整（不含 JSON 格式要求，格式要求约 650 token） |
| 再多 | HTTP 200，不报错，`prompt_tokens` 固定为 8194（上下文的一半 + 2），模型丢了指令 |

结论：**30 道题放得下，撑满上下文的是去重用的已有知识点**（`DedupContext` 把用户全部知识点的标题发给模型）。加上格式要求，16384 时大约能带 650 个标题。作者现在有 226 个。

## 决策

### 1. 不改每批题数，也不裁剪去重列表

题数不是瓶颈，改了解决不了问题。裁剪去重列表会悄悄降低去重质量，现在还用不上。

### 2. 比较估算值和实际用量，判断提示词有没有被截断

`LlmService` 的结构化调用拿到响应后，按“中日韩字符和全角符号 1 个 token，其余 3.5 个字符 1 个 token”估算发送内容，实际 `prompt_tokens` 不到估算值的 60% 就算截断，抛出 `LLM_CONTEXT_EXCEEDED`。

| 情况 | 实际 / 估算 |
| --- | --- |
| Ollama，完整 | 0.80～0.86 |
| DeepSeek，抽取，带 226、800 个标题（自造标题，含数字） | 0.77、0.73 |
| DeepSeek，源码 | 0.89 |
| Ollama，截断 | 0.27～0.41 |

这两段能分开不是巧合：Ollama 截断时只留上下文的一半，而提示词又超过了整个上下文，所以比值最多是正常比值的一半左右，不随上下文长度变化。

用比值，不判断是否等于 8194：这个数随上下文长度变，后端不知道用户把上下文设成了多少。

### 3. 按调用失败处理，不重试，不算模型出错

`LLM_CONTEXT_EXCEEDED` 是 `LlmException`，抽取的现有处理会记下返回码、不重试、后面的批次同样失败，页面显示 `failureReason`，抽取流程的代码不用改。内容不变时重试结果一样。

和不支持图片一样（决策 044），不调用 `fail(...)`：模型本身没有坏，不该让头像出现红点。判断放在空正文之前，提示词残缺时后面的结果都不可信。

放在 `LlmService` 而不是抽取流程里，题目切分、评分建议也走这里，一起受益。

## 验证

隔离的数据库和后端，走真实的导入和抽取：

| 模型 | 已有知识点 | 结果 |
| --- | --- | --- |
| Ollama | 800（自造标题，比真实标题长） | 9 秒失败，页面显示新提示，模型状态正常 |
| Ollama | 650（同上，估算约 2.6 万，确实超了） | 同上 |
| Ollama | 0 | 抽取成功，30 个知识点 |
| Ollama | 226（同上） | 10 分钟超时，`LLM_TIMEOUT`，只跑了一次，原因没查 |
| DeepSeek | 226、800 | 抽取成功，没有误报 |

## 放弃的方案

- **每批题数可配置**：瓶颈不在题数。
- **新增上下文长度配置，按它切批**：要和 Ollama 的设置手动保持一致，多一个容易配错的项。
- **超长时只发一部分标题**：会悄悄降低去重质量。
- **只判断 `prompt_tokens` 是否等于上下文一半加 2**：后端不知道上下文长度。
- **只在抽取流程里判断**：切题、评分建议受益不到。

## 已知限制

- 流式的学习对话拿不到用量，这次覆盖不到。#90 把源码放进对话时要再考虑。
- 比值只在 `qwen2.5:7b` 和 DeepSeek 上验证过。如果某个服务商返回的 `prompt_tokens` 明显偏小（例如不计入缓存命中的部分），正常的调用会被误判。没有返回用量的服务商不判断。
- 输出把上下文写满时没有信号：实测提示词 15237 + 输出 4271，超过 16384，结束原因仍是 `stop`。
- 用户调不大上下文时，只能得到明确提示，抽取仍然做不了。
- 本地模型的能力问题不在这次范围内：同一批题用真实题库时，`qwen2.5:7b` 校验没通过（编造知识点编号、漏题）；已有知识点多时可能超时。
