# 010 许可证改为 AGPL-3.0

## 背景

项目创建时使用 MIT 许可。按 PRD，项目既要开源供自部署，也要由作者部署线上版（M3）。MIT 允许任何人拿这份代码直接提供收费的线上服务，不需要公开修改，也不需要回馈。作者是目前唯一的贡献者，改许可证不需要征得他人同意。

同时讨论过申请专利：设计文档早已在公开仓库中发布，中国专利要求申请前未公开，自行公开不适用宽限期；核心思路（AI 对话学习 + 间隔重复）也难以证明创造性。因此不申请专利，仓库保持公开。

## 决策

1. **许可证从 MIT 改为 GNU AGPL-3.0**，从本次提交起生效
2. 移植自 py-fsrs（MIT）的代码保留原版权声明，继续记录在 `THIRD-PARTY-NOTICES.md`
3. 不申请专利，仓库保持公开；需要时另行考虑注册“温故”商标

## 理由

- **AGPL 针对的正是线上服务**：GPL 只在“分发软件”时要求公开源码，别人改完部署成网站并不算分发；AGPL 把“通过网络向用户提供服务”也算在内。这正好覆盖“别人拿去做竞品线上服务”的情况
- **不影响正常使用**：个人学习、自部署、修改后自用都不受限制，只有对外提供修改版服务时才需要公开源码
- **兼容现有依赖**：MIT、Apache-2.0 许可的代码可以合并进 AGPL 项目；MySQL Connector/J 是 GPL 加 FOSS 例外，可以和开源项目一起使用
- **现在改成本最低**：只有一个作者，没有外部贡献，不需要任何人同意

## 影响

- 本次之前已经按 MIT 发布的提交，别人仍然可以按 MIT 使用，改许可证不能追溯
- 以后接受外部贡献时，贡献按 AGPL-3.0 提交；如果将来要再改许可证或做商业授权，需要贡献者同意，届时再考虑是否引入贡献者协议（CLA）

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 保持 MIT | 他人可以不公开修改直接做线上服务，与作者自己部署线上版的计划冲突 |
| GPL-3.0 | 只约束分发，不约束网络服务，挡不住“改完直接部署成网站” |
| 源码可见但限制商用的许可（如 BSL） | 不属于开源许可，与 PRD“开源、可自部署”的定位不符，也会劝退贡献者 |
| 申请专利 | 设计已公开，新颖性很可能丧失；思路难证明创造性；费用和周期对个人项目不划算 |
| 仓库先设为私有 | 已公开的内容收不回来；作者决定保持公开 |
