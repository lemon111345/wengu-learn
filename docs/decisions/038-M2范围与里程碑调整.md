# 038 M2 范围与里程碑调整

## 背景

M1 复盘（[docs/retros/M1.md](../retros/M1.md)）发现：工期按写代码的时间估不准；建造挤占了使用，知识库有 226 个知识点，评分只有 10 次，还没有一天完成当天的全部任务；待办散落在 PRD、决策、issue 和对话中，汇总出一百三十多条。

同时，上线有了明确的目标：赶在春招和暑期实习招聘之前，2027 年 2 月底公开上线。原来的版本规划（M2 自用与开源、M3 线上版）没有默认卡组和技能体系的位置。

本决策记录里程碑的调整和由此带来的范围变化。逐条的去向见 M1 复盘的附录二。

## 决策

### 1. 里程碑

| 里程碑 | 内容 | 关卡 |
| --- | --- | --- |
| M2 自用与开源 | 自用反馈、Session 存进 Redis、统计最小版、老师的称呼、截图导入、源码导入与追问、自用数据复盘、发布 v0.1 | 连续自用 14 天；自部署版 v0.1 发布 |
| M3 默认卡组与技能体系（新增） | 默认卡组、技能体系（决策 033）、按参考答案重写要点、系统设计题的学法 | |
| M4 线上版（原来的 M3） | 免费额度与限流、用户自带 Key、模型降级链、“上线前必须完成”清单，加上主体与合规 | |

各阶段不写周数，依赖使用数据的事按“攒够多少次使用”来排。目标是 2027 年 2 月上中旬内测，2 月底公开上线。

**旧文档中的“M3”指现在的 M4。** 决策 004、007、010、013、017、022、032 和 M0、M1 复盘是当时的记录，不逐个修改。PRD、技术方案、ui.md 已经同步。

### 2. 14 天的算法（修订决策 007 第 5 点）

连续自用 14 天不再从“开始自用”线算起，改为按决策 020 的口径，从第一个完成全部任务的学习日起算。

### 3. 功能的去向

| 功能 | 原来 | 现在 | 原因 |
| --- | --- | --- | --- |
| 候选知识点（#31） | Must，M2 | Should，M2 末看数据 | 按 PRD 的 Must 标准（没有它，闭环还能跑通吗），它不是 Must。修订决策 008 |
| 从一个问题开始（#54） | Should，M2 | 之后，M2 末看数据 | 依赖候选知识点，需求也有待确认 |
| 模型降级链 | M2 | M4 | 自用和自部署都不急；决策 032 中的“降级链（M2）”以这里为准 |
| 按参考答案重写要点 | M2 | M3 | 生产默认卡组时用得上 |
| 学习统计 | M2 | 拆开：时长和连续天数 M2，其余之后 | 关卡只需要这两项 |
| 内置示例题库 | 想法池 | 并入默认卡组 | 目的相同 |
| Session 存进 Redis | 上线前 | M2 提前完成（#86） | 自用时每次重启后端都要重新登录。修订决策 034 |

老师的称呼（#53）和截图导入（#88）留在 M2：规划时一度分到想法池，作者最后决定 M2 直接做。

### 4. 内测和公开上线的区别

“上线前必须完成”的适用范围是公开上线。内测面向熟人、规模小，只要求有反馈渠道和简单统计。

### 5. 待办的管理

以后待办只放在 issue 中。决策的“遗留问题”只记录当时的取舍。零碎的小问题标为“碰到再修”，不建 issue。

### 6. PR 约定

写进 CLAUDE.md：只改文档的 PR 可以不建 issue，但要写明原因；chat、review、plan 模块的 PR，描述中要有“关键取舍”一节。

## 理由

- **M3 单独放默认卡组和技能体系**：默认卡组是新用户冷启动和技能亮度的分母，要在线上版之前准备好
- **14 天从完成全部任务算起**：只是打开用过不能说明闭环能坚持；决策 020 已经定了这个口径
- **不改旧决策的正文**：它们记录的是当时的判断；用一份新决策说明对应关系，比逐份修改更不容易出错

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 把默认卡组和技能体系放进线上版 | 线上版的工作已经很多，默认卡组的生产和审核又依赖时间，混在一起容易互相拖住 |
| 14 天仍从“开始自用”线算起 | 11-02 以来没有一天完成当天的全部任务，这样算没有意义 |
| 逐份修改旧决策中的 M3 | 改动面大，也会抹掉当时的上下文 |
| 为每条遗留问题建 issue | 大部分是碰到才需要处理的小问题，建了也只是换个地方堆着 |

## 遗留问题

- 默认卡组还是草案（PRD“待决问题”），M3 的 issue 等方案定了再建
- M3、M4 的关卡还没有定
- 技能树的来源和“用户只确认，不配置”的冲突（决策 033“待讨论”）
