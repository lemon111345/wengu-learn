# 温故 · PRD v0.1

## 背景与定位

**一句话定位：别再背八股了。讲给 AI 听，它追问到你真懂为止，然后在你快忘的时候再来问你。**

**核心理念：学习的关键是输出，而不是反复看答案。** 温故和题库类产品的本质区别是：题库让用户看懂答案，温故让用户自己说出答案，由 AI 追问检验是否真懂，再由 FSRS 在快忘时安排复习。用户导入资料即可每天按计划学懂、记住，不需要会写 prompt，也不需要配置标签。

很多人想用 AI 学习，却不会用：不知道该问什么、学完就散、没有复习。墨墨背单词这类工具证明了“每天少量新知识 + 按记忆规律复习”的编排很有效，但它只适合可以死记的内容。

本项目把两者结合：AI 负责拆知识点、出题、追问、结合用户自己的项目讲解；调度算法（FSRS）负责决定每天学什么、什么时候复习。用户只需要导入资料，然后每天打开、完成当天任务。

**宽与窄：** 方法是通用的（输出 + AI 检验 + 间隔复习），切入点是窄的。第一版的内容和宣传只聚焦面试，但技术架构按通用学习设计，知识点、调度等核心模型不与“面试”绑定。以后扩展到其他学习领域是增加内容，不是重写系统（见“学习原则”最后一段）。

**差异化：**

| 产品类型 | 有什么 | 缺什么 |
| --- | --- | --- |
| 题库类 | 内容 | 记忆调度：看过就算，不知道什么时候该复习 |
| AI 模拟面试类 | 追问 | 用完即止：不记录、不安排复习 |
| 通用间隔复习工具 | 记忆调度 | 不懂面试：只能翻卡片自评，检验不了是否真懂 |

温故的重点是把 FSRS 调度和 AI 判断是否真懂结合起来，并长期追踪。

**同类开源项目：** JavaGuide 的 InterviewGuide 等开源项目和温故的技术栈几乎一样，技术栈本身不是亮点。亮点要放在 FSRS 建模、AI 评判与调度的结合上。

## 目标用户与使用场景

**第一版目标用户：国内计算机专业、Java 后端方向的学生**，包括正在学 Java 的低年级学生和准备求职的高年级学生。他们同时面对“八股文”和“项目深挖”两类问题，手里有面试题、项目源码和学习资料，但缺少系统的复习安排。用户的主要来源是手机（见“上线前需要评估”）。

典型场景：

- 每天花 30～60 分钟准备面试，打开就知道今天学哪几个知识点、复习哪几个。
- 面试前想把自己项目里的代码真正讲清楚，而不是只背项目介绍。
- 资料散落在 PDF、笔记和代码里，希望一次导入、统一管理。

**第一版的第一个用户就是项目作者本人**，先自用验证闭环，再开放给其他人。

## 核心使用流程

用户只在开始时导入一次资料，之后每天的使用都在闭环里转：打开计划、逐个对话学习、确认评分，调度算法决定它下次什么时候再出现。

```mermaid
flowchart LR
    A[导入资料<br/>面试题、源码、文档] --> B[抽取知识点<br/>AI 拆分，用户确认]
    B --> C[每日计划<br/>新知识 + 到期复习]
    C --> D[学习对话<br/>讲解、提问、追问]
    D --> E[评分确认<br/>AI 建议，用户确认]
    E --> F[FSRS 调度<br/>算出下次复习时间]
    F -- 到期后回到计划 --> C
```

对应的用户故事：作为准备面试的学生，我希望每天打开就知道该学什么，学完一个知识点就能确认掌握程度，而不用自己记哪些该复习了。

## 学习原则

设计学习流程时以下面六条为依据。它们和学什么无关，是以后扩展到其他学习方向时不变的部分：

| 原则 | 意思 | 在温故中的体现 |
| --- | --- | --- |
| 从已有知识出发 | 新知识要挂在旧知识上；基础缺了，学得又慢又浅 | 对话先摸底；不会的基础成为候选知识点 |
| 小步、少量 | 一次只能处理几块新信息 | 知识点粒度标准；每次只讲一小段；对话轮数有上限 |
| 先想后讲 | 先让学生猜、推理，再讲解，记得更牢 | 摸底、“下一步会发生什么” |
| 主动回忆 + 反馈 | 回忆比重读有效，也是唯一可靠的检验：听懂不等于能讲出来 | 检验、追问、完整作答、复习 |
| 间隔 | 分散到多天学，比一次学很久有效 | FSRS 调度 |
| 针对薄弱点 | 练还不会的，不重复已经会的 | 复习时针对上次没掌握的点提问 |

**从问题倒推着学**：以面试题为起点，只学回答它需要的内容，遇到不会的就顺着问下去。目标明确、效率高，但容易零散、学完就忘，所以要配上两件事：完全没有基础时，先讲最少必要的基础；倒推中新接触到的内容，收进复习计划（“接着问”和候选知识点）。

不同学习方向的区别主要在“回忆”的形式：面试题和概念原理要**讲出来**，数学和算法要**做出来**，外语要**用出来**，网安、嵌入式、游戏开发等技能要**动手做**，单词和公式只需**记住**。扩展到其他方向时，闭环不变，主要是增加知识点类型（各有自己的教法和检验方式）和导入方式。

## AI 的原则

技术上的做法（模型接入、Agent 的安全原则）见技术方案“AI 模块的原则与阶段”。

- **固定流程优先**：能用固定流程解决的 AI 功能，不做成 Agent。固定流程包括：答题评判（AI 点评并建议评分，用户确认）、知识点内的讲解追问、导入出题
- **Agent 的定位**：不做开放式问答助手，而是“有目标、有数据、能动手的备考教练”。判断标准：**这件事用户直接问自己的 AI 能做得一样好吗？能就不做**
- **作答方式：输出是核心。** 主路径保持让用户自己作答，不提供“只看答案自评”作为主路径。降低作答成本的方向是语音作答：第一阶段依靠手机输入法的语音输入，不自行接入语音识别

## 版本规划

自部署和线上都要做，但按顺序来：**先用自部署版验证闭环，再加免费额度和用户自带 Key。** 线上版涉及计费和 Key 安全，工作量不小，提前做容易拖住核心功能。账号注册登录在 M1 就做，自部署和线上用同一种模式（决策 017）。

| 阶段 | 内容 | 进入下一阶段的关卡 |
| --- | --- | --- |
| M0 技术验证 | 测试知识点抽取 prompt；移植 FSRS 并测试 | 抽取质量达标 |
| M1 自部署闭环 | 实现全部 Must 功能；注册登录，Docker 启动 |  |
| M2 自用与开源 | 连续自用并修问题；每天学习总量、评分修改等自用反馈；Session 存进 Redis；统计最小版；老师的称呼；截图导入；源码导入与追问；前置知识点；自用数据复盘；写 README 并发布 | 连续自用 7 天（按决策 020 的口径，从第一个完成全部任务的学习日起算，决策 046）；自部署版 v0.1 发布 |
| M3 默认卡组与技能体系 | 默认卡组（草案见“待决问题”）；技能体系（决策 033）；按参考答案重写要点；系统设计题的学法；前置知识点在 M2 先做（决策 046） |  |

## 明确不做与想法池

**第一版明确不做：** 由用户手动创建和维护的标签、分类系统（知识点的技能归属由系统图谱和 AI 决定，用户只确认，不配置，见决策 033）、手动番茄钟、产品内用户之间的题库分享（官方图谱和知识点模板放在仓库中，接受 PR 贡献，见决策 033）、移动端 App（以后的小程序见决策 034）、MCP 集成、多人协作。

想法池（新想法先记在这里，MVP 之后再评估）：

- 手动专注计时与自定义备注
- 把温故做成 MCP Server：让用户在自己的 AI 客户端（Claude Code 等）中查询学习数据，也可以在其中学习
- 题库市场：用户分享整理好的知识点集合
- 根据会话时长自动调整知识点难度
- 组队学习打卡（M4 之后评估）：2～3 人，参考墨墨背单词，通过邀请链接加入。只打卡不聊天：组员能看到彼此当天是否完成和连续天数，有小组连续天数（全员完成才算一天）；轻互动只用预设内容（“催一下”每天限一次、完成后的固定回应），不开放自由文字；组员各按自己的学习日；组内只共享打卡结果，不共享知识点和资料。连续的口径与个人连续学习相同，见决策 020
- 个人经历题在没有源码时，AI 帮用户梳理经历（问题、选择、结果），M2 与源码追问一起考虑
- 简历防守：简历作为输入，拆成一条条声明，生成需要扛住的追问并进入复习；不做简历编辑器。个人经历类知识点可作为它的基础
- 技能树页面：导航中单开一项，和今天、知识库并列，技能点亮带来成就感和正反馈（技能体系的数据和亮度计算在 M3，见决策 033）
- 技能树的来源：根据 JD 生成；用户添加技术栈；或者做一个技术栈库，用户直接选，并支持自定义。其中用户添加、自定义的部分和“用户只确认，不配置”有冲突，见决策 033“待讨论”
- JD 匹配与面试冲刺规划
- 基于用户项目和薄弱知识点的模拟面试，结束后自动生成复习内容
- 面经复盘：用户贴入真实面试被问到的题，整理成知识点并诊断薄弱点
- 把用户和其他 AI 的对话导入，提炼成知识点

## 关键约束

**费用：** 自部署版只用用户自己的 API Key 或本地模型，作者零成本。线上版提供少量免费额度，额度用完后引导用户填自己的 Key；每个用户的用量按天计数并限流，防止被刷。

**模型：** 线上版部署在中国内地，因此线上版只支持国内模型。自部署版不受此限制，兼容 OpenAI 格式的服务和本地 Ollama 都可以用（决策 004）。

**API Key 安全：** 用户 Key 加密后入库，加密密钥放在环境变量里，不写进代码和数据库；接口返回时只显示末四位；日志中不打印 Key。

**隐私：** 用户上传的源码和资料只用于该用户自己的学习，不用于其他用途；自部署版数据完全留在用户机器上，这是面向开发者的重要卖点。

**架构要求：** 自部署和线上用同一套代码，只有多用户模式：都要注册登录，不设管理员，是否开放注册由环境变量控制，避免维护两个版本。界面上不出现部署和配置相关的文字，这些写在 README，见决策 017。
